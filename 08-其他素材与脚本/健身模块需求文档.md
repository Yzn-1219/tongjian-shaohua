# 个人知识库 · 健身模块需求文档（PRD）

> 版本：v1.0
> 日期：2026-08-24
> 范围：仅健身相关功能（训练记录、身体数据、AI 教练、每日总结、目标设定、数据同步），不含笔记/语音/知识库通用能力本身（通用能力仅在与健身交叉处描述）。
> 说明：本文档基于当前已实现代码（v1 线上版）整理，并补充明确的产品预期与验收标准。「已实现」标注当前代码已具备；「规划」为建议增强项。

---

## 1. 背景与目标

用户使用「个人知识库」App（安卓 + 网页 + PWA）记录生活与训练。健身是其中最高频、最需要量化追踪的场景，核心诉求是：

- **极简录入**：用一句话/一段语音就能记一次训练（"卧推4×8 70kg""跑步30分钟"），系统自动识别部位、组次、重量、时长。
- **长期可追踪**：按日期沉淀训练与身体数据，自动生成周运动量、体重趋势、连续打卡等可视化。
- **AI 辅助**：基于历史数据给出每周分析、明日训练建议、营养建议，并生成每日文字总结。
- **多端共用一份数据**：手机记、网页看/改，云端（Supabase）实时同步。

## 4. 详细功能需求

### 4.1 训练记录（F-TR）

**录入方式（4 种，互斥但可组合）**
1. **部位 + 自由文本**：在 9 个部位 chip 中选一个，文本框写入动作（如"卧推 4×8 @70kg"）。
2. **快捷模板**：点击预设模板一键填入（跑步30min / 卧推4×8 / 引体向上4×8 / 深蹲5×5），自动带出对应部位。
3. **自然语言输入框**：直接写"今天练胸 卧推4×8 夹胸3×12"，系统自动解析（见 4.2）。
4. **语音转写后写入**：通过语音浮层录完 → 转写文本 → 送入同一解析与保存流程（语音能力见通用模块，此处仅消费其输出）。

**字段定义（每条训练记录）**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `date` | string(YYYY-MM-DD) | 是 | 记录日期，默认当天；格式 `toISOString().slice(0,10)` |
| `partId` | string | 是 | 部位 id（chest/back/.../rest） |
| `part` | string | 是 | 部位中文名（冗余存储，便于展示与云端检索） |
| `exercises` | string | 是 | 动作描述文本，可多行 |
| `duration` | int(分钟) | 否 | 时长；未填时由语义解析兜底 |
| `calories` | int(kcal) | 否 | 消耗；未填时由 `MET×时长` 估算 |
| `isRest` | boolean | 是 | 是否休息日 |
| `created_at` | bigint(ms) | 是 | 创建时间戳 |

**保存逻辑**
- 用户手动填了时长/消耗 → 以手动为准。
- 用户未填 → 用 `TrainingParser.parse()` 结果兜底（时长、消耗、部位）。
- 手动选了部位 chip → 以手动部位为准；否则取解析出的部位。
- 保存后清空输入框、重新渲染健身页、Toast 提示"已保存训练记录"。

**历史展示**
- 卡片列表（默认最近 10 条），含：日期（`M月D日 周X`）、部位标签（带色块）、动作（每行前加 `•`）、时长与消耗。
- 休息日用特殊灰卡："😴 休息也是训练的一部分"。

### 4.2 自然语言模糊语义解析（F-PARSE，核心）

纯本地算法（`training-parser.js`），毫秒级、不联网，是健身录入的灵魂。

**4.2.1 部位识别（关键词命中，取最早出现者）**

| 部位 id | 中文 | 关键词示例 |
|---------|------|-----------|
| cardio | 有氧 | 跑步/跑/快走/游泳/骑车/跳绳/椭圆/划船机/爬楼/hiit/波比/动感 |
| chest | 胸部 | 卧推/推胸/胸/夹胸/飞鸟/俯卧撑/双杠 |
| back | 背部 | 引体/背/划船/下拉/硬拉/背阔 |
| legs | 腿部 | 深蹲/腿/箭步/臀/髋/提踵/腿举/保加利亚/臀桥 |
| shoulder | 肩部 | 推举/肩/侧平举/前平举/后束/面拉/阿诺德 |
| arms | 手臂 | 弯举/臂/二头/三头/臂屈伸/锤式/肱二/肱三 |
| core | 核心 | 平板/卷腹/核心/腰腹/仰卧起坐/俄罗斯/悬垂举腿/腹肌 |
| stretch | 拉伸 | 拉伸/瑜伽/放松/舒展/泡沫轴/开肩 |
| rest | 休息日 | 休息/没练/躺平/歇/恢复日/没动/偷懒/放假 |

> 规则：rest 权重最低，仅在没有其他部位命中时才判为休息日；多条命中取文本中**最先出现**的关键词所属部位。

**4.2.2 时长提取**
- 中文特殊表达：`半小时/半个钟`→30；`一小时/一个钟`→60；`两小时`→120；`一个半小时`→90。
- 数字+单位：`(\d+)(分钟|分|min|m)`；兜底 `(\d+)分钟`。
- 返回整数分钟；识别不到为 0。

**4.2.3 组次提取** `setsReps: [{sets, reps}]`
- 符号式：`4×8` / `4x8` / `4*8`。
- 中文式：`4组8次` / `4组8个` / `4组8下`。
- 残缺式：仅"4组"或"8次"也记录（对应字段为 0）。
- 同一组合去重。

**4.2.4 重量提取**（kg）
- `@70kg` / `70kg` / `70公斤` → 70。
- 市斤 `140斤` → 折算 70kg（÷2）。
- 取第一个重量。

**4.2.5 置信度**
- 命中部位 +0.5；命中时长/组次/重量任一 +0.3（否则 +0.1）；文本长度>2 再 +0.2，上限 1.0。
- 预览中：`≥0.8🟢 / ≥0.5🟡 / 其他🟠`。

**4.2.6 消耗估算**
- `calories = duration × metRate[partId]`（metRate：cardio 8 / legs 6 / chest·back 5 / shoulder 5 / arms 4 / core 4 / stretch 2 / rest 0）。

**4.2.7 展示文本重组**
- 去人称/时间前缀（我/今天/刚…）、去标点、去句尾语气词（了/啦/嘛）。
- 自动拼回 `动作 4×8 @70kg 30min` 形式（仅补全缺失维度）。

**4.2.8 实时预览**
- 输入框输入后 350ms 防抖触发，显示"识别为<b>部位</b> · N分钟 · 组次 · 约M kcal + 置信度图标"，并自动预选部位 chip 与填入时长（用户可改）。

> 规划：解析结果应支持「编辑后保存」「忽略解析直接存原文本」两种确认态；长文本多动作（"练胸 卧推4×8 夹胸3×12"）应能拆成多条动作行而不仅是单段。

### 4.3 休息日标记（F-REST）
- 选「休息日」chip，或文本命中休息关键词（见 4.2.1），即记一条 `isRest=true` 的训练。
- 历史卡、周图表、首页统计均识别休息日：周图表中 0 时长显示 rest 样式；首页"训练数"统计排除休息日。

### 4.4 本周运动量柱状图（F-WEEK）
- 以**周一**为一周起点，取本周一至周日区间 `[weekStart, weekEnd]`。
- 每天高度 = 当天训练记录中的**最大** duration（分钟）。
- 今天列半透明；无训练列呈 rest 样式。
- 纵轴基准 60 分钟（不足时按比例缩放，最小 8px/休息 4px）。

### 4.5 体重与身体成分（F-BODY）

**4.5.1 体脂秤蓝牙连接**
- 技术：Web Bluetooth（`navigator.bluetooth`）。
- 目标设备：米家体脂秤系列（Mi Scale 2 等），服务 UUID `181D`，特征 `2A9C`（Weight Measurement）。
- 设备过滤：`MI` / `MIBCS` / `MIBFS` 前缀或服务过滤。
- 交互：`connectScale()` → 系统弹窗选设备 → 站秤 → 稳定后自动读数并保存 → 断开。
- 兼容：不支持蓝牙的环境（部分桌面浏览器）提示"请在手机端使用"；`NotFoundError` 提示"未找到体脂秤，请确认已开蓝牙"。

**4.5.2 数据解析与估算**
- 体重：小端 16bit，单位 50g（部分固件 0.01kg 回退），保留 1 位小数。
- 阻抗（有体脂数据时）：用于估算体成分，需用户基础数据 身高/年龄/性别。
- 估算公式（简化，规划可接权威算法）：
  - BMI = 体重 / 身高(m)²
  - BMR = `10×体重 + 625×身高m − 5×年龄 + (男5/女−161)`
  - 体脂率 = `1.20×BMI + 0.23×年龄 − (男16.2/女5.4) + 阻抗修正`，夹在 5%~50%
  - 肌肉量 ≈ 去脂体重×0.55；水分率 ≈ 去脂体重/体重×70%；骨量 ≈ 体重×3.5%；蛋白质 ≈ 去脂体重/体重×18%

**4.5.3 身体成分卡**
- 展示 8 项：体重 / 体脂率 / 肌肉量 / 骨量 / 水分率 / 基础代谢 / BMI / 蛋白质。
- 无数据态：显示"🔗 连接体脂秤"，点击触发连接。

**4.5.4 体重趋势图**
- 取最近 30 天体脂秤数据，SVG 折线 + 面积渐变。
- 显示最新体重与**增减 delta**（红涨绿跌，遵循国内习惯）；无数据提示"连接体脂秤后自动生成趋势图"。

### 4.6 AI 健身教练（F-COACH）
- 输入：近 20 条训练 + 近 5 条身体数据 + 健身配置（目标/基础数据）。
- 输出（JSON）：
  - `analysis`：本周训练分析（频率、强度、薄弱环节）
  - `suggestion`：明日训练建议（部位/动作/组次/时长）
  - `exercises[]`：推荐动作标签
  - `nutrition`：营养建议（结合目标与训练量）
  - `progress`：0-100 进度
- 目标进度条：当前体重 → 目标体重 的完成百分比（`1 − |目标−当前| / |目标−起点|`）。
- 厂商：独立 `coach` 类 AI 配置（默认智谱 GLM），与笔记/语音/总结分开。
- 交互：加载态"🤔 AI 教练正在分析…"；"↻ 刷新"重新生成。

### 4.7 目标设定（F-GOAL）

**训练目标**
| 字段 | 说明 |
|------|------|
| `goal` | build(增肌) / cut(减脂) / maintain(维持) |
| `targetWeight` | 目标体重 kg |
| `targetBodyFat` | 目标体脂率 % |
| `targetDate` | 截止日期 |
| `weeklyFreq` | 每周训练频率目标（次） |

**营养目标**
| 字段 | 说明 |
|------|------|
| `dailyCalories` | 每日热量目标 kcal |
| `dailyProtein` | 每日蛋白质 g |
| `dailyCarbs` | 每日碳水 g |
| `dailyFat` | 每日脂肪 g |

**基础身体数据**（估算体成分/教练建议用）
- `height` / `weight` / `bodyFat` / `age` / `gender`(male/female)

> 存储位置：本地 `config.fitness`（随 App/网页配置），**不进云端**（属个人偏好；规划可同步到云端 profiles）。
> UI：设置页「健身」分区，含基础数据、训练目标、营养目标三组输入。

### 4.8 每日 AI 总结（F-SUMMARY）
- 维度：**按日期**（默认今天，可切历史日期）。
- 聚合当天：
  - 笔记数 `noteCount`、训练数 `trainCount`、训练总时长 `trainDuration`
  - 心情 `mood`（用户可标记）
- AI 生成（`AI.generateSummary`）：基于当天笔记 + 训练，输出：
  - `summary`：80-150 字总结
  - `topics[]`：主题词
  - `score`：1-100 当日效率分
  - `highlights[]`：亮点
- **时间线 Timeline**：当天事件流，含笔记（📝+时间）与训练（💪/😴+动作），按时间排序。
- 无 API Key 时降级：仍显示基础统计 + "点击下方生成 AI 总结"。
- 存储：云端 `summaries` 表，`date` 为主键（每日一份，覆盖更新）。

### 4.9 首页健身概览（F-HOME）
- 近 7 天训练统计：本周训练天数、训练次数、今天训练数。
- **连续打卡天数 (Streak)**：从今天往前数连续有训练记录（非休息）的天数。

### 4.10 数据层与多端同步（F-DATA）
- 本地：IndexedDB 三张表 `trainings` / `bodydata` / `summaries`，`trainings` 建 `date` 索引。
- 云端：Supabase 同构表（见第 6 节），通过 `CloudDB` 直连 PostgREST（不依赖 SDK）。
- 切换：配置 `storage.mode = local | supabase`；localStorage 优先，空时回退 `config.storage`。
- 同步语义：当前为"同源读写"（哪端写哪端读，无冲突合并）；规划：增加"本地草稿 + 手动/自动上云 + 拉取合并"。
- 导入导出：`exportAll/importAll` 支持 JSON 备份（含训练/身体/总结）。

## 5. 数据模型（云端 Supabase 表）

```sql
-- 训练记录
trainings(id bigint pk, date text, part text, part_id text, exercises text,
          duration int, calories int, is_rest bool, created_at bigint);

-- 身体数据（每天一条/多次取最新）
bodydata(id bigint pk, date text, weight numeric, body_fat numeric, muscle numeric,
         bone numeric, water numeric, bmr int, bmi numeric, protein numeric,
         impedance int, stabilized bool, created_at bigint);

-- 每日总结
summaries(date text pk, summary text, topics text[], score int, highlights text[],
          mood text, note_count int, train_count int, train_duration int,
          updated_at bigint);
```
> 说明：本地 IndexedDB 字段与云端一一对应；`tags` 类数组在云端用 `text[]`。

## 6. AI Prompt 规范（健身相关）

**每日总结（category=summary）**
```
系统：你是一个个人助理，负责生成每日总结。基于用户今天的笔记和训练记录，生成简洁总结。
      JSON: {"summary":"80-150字","topics":["..."],"score":1-100,"highlights":["..."]}
用户：日期 / 心情 / 今日笔记 / 今日训练（部位:动作(时长,消耗)）
```

**健身教练（category=coach）**
```
系统：你是专业私人健身教练AI。给出：1)本周训练分析 2)明日训练建议(部位/动作/组次/时长)
      3)营养建议。JSON: {"analysis","suggestion","exercises":[],"nutrition","progress":0-100}
用户：基础数据(身高/体重/体脂/年龄/性别) + 目标(增肌/减脂/维持 + 目标体重/体脂/截止日/周频率)
      + 最近训练记录 + 最新身体成分
```
> 约定：AI 类别独立配置厂商；失败/无 Key 时**绝不阻塞主流程**，降级为本地统计。

## 7. 日期与内容分析专项（用户重点关注）

**日期处理**
- 所有训练/身体/总结记录均以 `YYYY-MM-DD` 为业务日期主键。
- 周图表按"周一为起点"的本地周计算（非自然周）。
- 趋势/历史默认展示"最近 N 天/条"，可扩展为自定义区间筛选（规划）。
- 总结严格按"天"聚合，`created_at` 时间戳用于判断归属日期与排序。

**内容分析（Content Analysis）覆盖点**
1. **录入即分析**：自然语言 → 结构化字段（部位/组次/重量/时长/消耗），见 4.2。
2. **训练聚合分析**：周运动量、连续打卡、今日概览（F-WEEK/F-HOME）。
3. **身体趋势分析**：体重折线 + delta、身体成分八维（F-BODY）。
4. **AI 语义总结**：每日文字总结 + 主题 + 效率分（F-SUMMARY）。
5. **AI 行为建议**：周分析 + 明日训练 + 营养（F-COACH）。
6. **规划-检索分析**：按部位/日期/关键词筛选、导出统计报表（F-SEARCH）。

## 8. 非功能需求

- **离线优先**：无网时可录入、可看本地历史；联网后同步云端。
- **隐私**：AI Key / Supabase key 仅存本机，不进代码仓库；云端表用 anon key + RLS。
- **性能**：语义解析本地毫秒级；图表基于最近 30 条数据，渲染轻量 SVG。
- **多端一致**：安卓 App 与网页共用同一套 `fitness.js / training-parser.js / scale.js / summary.js`，行为一致。
- **容错**：蓝牙/AI/网络任一失败均降级，不阻断记录。

## 9. 验收标准（可测）

| 项 | 验收 |
|----|------|
| 录入 | "卧推4×8@70kg" → 部位=胸、组次=4×8、重量=70、置信度🟢 |
| 休息日 | 文本"今天休息" → 历史显示休息卡，不计入训练数 |

| 体脂秤 | 手机端连米家秤，站上自动写入体重+估算体成分 |
| 体重趋势 | 连测 2 天出现折线 + delta |
| AI 教练 | 有训练数据时点生成，返回 analysis/suggestion/exercises/nutrition/progress |
| 每日总结 | 选某日期生成，含 80-150 字 + 时间线；无 Key 降级统计 |
| 目标进度 | 设目标体重后教练卡显示进度百分比 |
| 同步 | 网页/App 任一端写入，另一端刷新可见（Supabase 模式） |
| 连续打卡 | 连续 3 天有训练 → Streak=3 |
